# DRF LMS Project
Веб-приложение для управления обучением (LMS) с использованием Django REST Framework.
Проект успешно контейнеризирован с использованием Docker и Docker Compose.

### Домашнее задание 35.2 — CI/CD и Деплой

В рамках задания успешно выполнены следующие шаги:
1. **Контейнеризация и Сервер**: Проект переведён на промышленный WSGI-сервер **Gunicorn** и настроен обратный прокси-сервер **Nginx** для раздачи статических файлов.
2. **Оркестрация**: Обновлён файл `docker-compose.yaml`. Для внутренних сервисов (БД и Redis) используется `expose` вместо `ports` для изоляции сети. Настроены `volumes` для персистентности данных.
3. **Конфигурация**: Создан чистый шаблон переменных окружения `env.template`.
4. **CI/CD Автоматизация**: Написан сценарий GitHub Actions (`main.yaml`). Реализованы этапы автоматического линтинга (`flake8`), запуска Django-тестов и симуляции деплоя по SSH через GitHub Secrets.

*Примечание:* Из-за ограничений прав доступа Personal Access Token (PAT) к скрытым директориям, файл автоматизации GitHub Actions временно сохранён в корневой папке `github-workflows/`.


## Новые фичи
* **Фоновые задачи (Celery):** Настроена интеграция с Celery для вынесения тяжелых операций в асинхронный фоновый режим.
* **Рассылка уведомлений об обновлениях:** Реализована Celery-задача `send_course_update_email`, которая автоматически рассылает email-уведомления всем подписчикам конкретного курса при изменении его материалов.
* **Ограничение частоты рассылок (Доп. задание):** Внедрено поле `updated_at` в модель курса. Рассылка писем подписчикам блокируется, если с момента последнего обновления курса прошло менее 4 часов.
* **Автоматическая блокировка пользователей:** Реализована периодическая задача `check_inactive_users` (`Celery Beat`). Раз в сутки система сканирует пользователей и переводит флаг `is_active = False` для тех, кто не авторизовался в системе (`last_login`) более 30 дней.
* **Батч-обновление базы данных:** Операция блокировки неактивных пользователей выполняется оптимизированным батч-запросом (`.update()`), исключая тяжелые циклы.
* **Синхронизация Таймзон:** Настройки `CELERY_TIMEZONE` жестко синхронизированы с глобальной временной зоной проекта Django для точного планирования.
* **Платежный эквайринг:** Подключена интеграция платежей через сессии Stripe с кодированием цен в копейках.
* **Автодокументация API (Swagger/Redoc):** Интегрирована библиотека `drf-yasg`. Настроена автоматическая генерация интерактивной документации всех эндпоинтов системы.
* **Интеграция с платежной системой Stripe:** Реализован механизм удаленного эквайринга для покупки курсов и уроков. Взаимодействие со Stripe вынесено в изолированный сервисный слой `services.py`.
* **Конвертация цен:** Реализована корректная передача стоимости материалов в Stripe — рубли автоматически переводятся в копейки (целое число).
* **Проверка статуса платежей:** Добавлен эндпоинт для запроса актуального статуса сессии оплаты из Stripe по её идентификатору с автоматической синхронизацией данных в локальной базе данных.
* **Валидация контента:** Реализована строгая проверка добавляемых ссылок с помощью кастомного класса `YoutubeUrlValidator`. К записи допускаются ссылки, ведущие исключительно на `youtube.com`. При ошибке возвращается понятный текст.
* **Система подписок:** Добавлена модель `Subscription`, связывающая пользователя с курсом с гарантией уникальности пары. Реализован эндпоинт-переключатель (`POST /materials/course/subscribe/`), который гибко добавляет или удаляет подписку.
* **Признак подписки в API:** В сериализатор курсов интегрировано динамическое поле `is_subscribed` (`SerializerMethodField`), отображающее статус подписки текущего авторизованного пользователя.
* **Пагинация (Постраничный вывод):** Настроена кастомная пагинация `MaterialsPagination` (`PageNumberPagination`) для списков курсов и уроков. Заданы параметры `page_size`, `page_size_query_param` и `max_page_size`.
* **Подсчет и вывод данных:** В эндпоинтах курсов выводится количество уроков (`lessons_count`) и их подробный список.
* **Модель платежей:** Добавлена сущность `Payment` с возможностью фиксировать оплаты курсов/уроков наличными или переводом.
* **Инструмент фикстур:** Подготовлены демонстрационные данные по платежам и автоматическое наполнение системных групп для быстрого развертывания БД.
* **Фильтрация и сортировка:** Подключен пакет `django-filter` для точного поиска платежей по курсу, уроку, способу оплаты и сортировке по дате.
* **JWT-авторизация:** Реализована безопасная аутентификация по токенам (Access/Refresh).
* **Права доступа и роли:** Внедрена группа «модераторы» с ограничениями на создание и удаление контента. Обычные пользователи могут управлять только своими курсами и уроками.
* **Приватность профилей:** В эндпоинте профилей реализовано динамическое скрытие данных (при просмотре чужого аккаунта пароль, фамилия и платежи автоматически скрываются).

## Как запустить проект локально

1. **Клонируйте репозиторий:**
```bash
git clone <ссылка_на_ваш_репозиторий>
cd drf_lms_project
```

2. **Создайте и активируйте виртуальное окружение:**
```bash
python -m venv venv
# Для Windows:
venv\Scripts\activate
```

3. **Настройте переменные окружения:**
* Скопируйте шаблон файла конфигурации:
```bash
cp .env.template .env
```
*(Если вы на Windows в PowerShell, используйте команду: `cp env.example .env` или вручную переименуйте скопированный файл в `.env`)*
* Откройте созданный файл `.env` и укажите в переменной `SECRET_KEY` ваш секретный ключ Django и секретный тестовый ключ Stripe (`STRIPE_SECRET_KEY`).
* Обязательно укажите параметры подключения к Redis:
```text
CELERY_BROKER_URL=
CELERY_RESULT_BACKEND=
```
4. **Установите все зависимости:**
```bash
pip install -r requirements.txt
```

5. **Примените миграции базы данных:**
```bash
python manage.py migrate
```
6. **Запустите сборку и оркестрацию контейнеров одной командой:**
   ```bash
   docker compose up --build
   ````
7. **Загрузите демонстрационные данные из фикстур:**
```bash
python manage.py loaddata users/fixtures/groups_data.json
python manage.py loaddata users/fixtures/payments_data.json
```

8. **Создайте суперпользователя (администратора):**
```bash
python manage.py createsuperuser
```
*Система попросит ввести Email и пароль (авторизация по умолчанию настроена через Email).*

9. **Запустите сервер разработки:**
```bash
python manage.py runserver
```
Проект будет доступен по адресу: `http://127.0.0`

## Примеры использования API (Эндпоинты)
* `http://127.0.0` — Главная страница-навигатор по проекту.
* `http://127.0.0/materials/courses/` — Список курсов со встроенными уроками и их счётчиком.
* `http://127.0.0/users/payments/` — Список всех платежей.
    * Сортировка по дате (от новых к старым): `?ordering=-payment_date`
    * Фильтр по способу оплаты: `?payment_method=cash`
    * Фильтр по курсу: `?paid_course=1`
* `http://127.0.0/users/token/` — Получение JWT-токенов (Авторизация).
* `http://127.0.0/users/token/refresh/` — Обновление JWT access-токена.
* `http://127.0.0/users/register/` — Регистрация нового пользователя (доступна без токена).
* `http://127.0.0/users/profile/1/` — Профиль пользователя. При просмотре своего профиля отдаётся полная информация, при просмотре чужого — скрываются личные данные.

## Работа с документацией API
После запуска сервера интерактивная документация доступна по адресам:
* **Swagger UI:** `http://127.0.0/swagger/`
* **Redoc:** `http://127.0.0/redoc/`

## Примеры использования Stripe API (Платежи)
* `POST /users/payments/create/` — Создание сессии оплаты курса/урока в Stripe. В ответе возвращается JSON с подробными данными платежа и полем `payment_link`, содержащим прямую ссылку на тестовую страницу оплаты Stripe Checkout.
* `GET /users/payments/status/<id>/` — Проверка статуса транзакции в Stripe по локальному ID платежа. При успешной оплате (`paid`) способ оплаты в БД автоматически обновляется.

## Тестирование и анализ покрытия
В проекте реализовано автоматическое тестирование сценариев CRUD для уроков, работы подписок и разграничения прав доступа для всех групп пользователей.

1. **Для запуска тестов с замером покрытия выполните:**
```bash
coverage run --source='.' manage.py test
```

2. **Для просмотра результатов замера в терминале или генерации отчёта:**
```bash
coverage report
# Генерация файла отчёта (сохранен в корне проекта):
# coverage report > coverage.txt
```
